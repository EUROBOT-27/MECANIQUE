Path Planning (RRT)
====================

This folder contains a simple Rapidly-Exploring Random Tree (RRT) planner implemented
for 2D navigation on the competition table.

Files
-----
- `rrt.py` : A lightweight, dependency-free RRT implementation with a single
  function `rrt_plan(start, goal, obstacles, bounds, max_iter=2000, step_size=0.25, goal_sample_rate=0.05)`.

Algorithm Overview
------------------
- The planner grows a tree of nodes in 2D (x,y) sampling uniformly in the workspace.
- With a small probability (`goal_sample_rate`) the planner samples the goal to bias growth.
- Each iteration:
  1. Sample a random point.
  2. Find the nearest node in the tree.
  3. Steer from the nearest node toward the sample by `step_size` producing a new node.
  4. If the segment from nearest->new_node does not collide with circular obstacles, append it.
  5. If the new node reaches within `step_size` of the goal, reconstruct the path and return it.

Obstacles and Collision
-----------------------
- Obstacles are modeled as circles: `(center: np.array([x,y,z?]), radius_meters)`.
- Collision checks are conservative: path segments are tested against each obstacle using
  a simple line-segment vs circle intersection test in 2D.

Usage Notes
-----------
- Inputs `start` and `goal` are array-like, at least `[x, y]`. The returned path is a list
  of 3D points with z=0 (i.e., `[x,y,0]`), which integrates cleanly with the rest of the pipeline.
- Tuning:
  - `step_size` controls granularity; smaller values produce finer paths but increase runtime.
  - `max_iter` limits runtime — increase if the planner often fails.
  - `goal_sample_rate` helps the planner bias growth toward the goal (useful in cluttered scenes).

Integration
The pipeline (`full_pipeline/scripts/main.py`) calls `rrt_plan` to compute paths.
The pipeline handles visualization and projecting the path into image coordinates for display.

RRT-Connect Algorithm
---------------------
`rrt_connect.py` implements the RRT-Connect algorithm, which is a faster variant of RRT for path planning.

Key Features:
- Grows two trees simultaneously: one from the start and one from the goal.
- At each iteration, the trees attempt to connect to each other, accelerating convergence.
- More efficient in cluttered environments and typically finds paths faster than standard RRT.

Usage:
- Call `rrt_connect_plan(start, goal, obstacles, bounds, max_iter=2000, step_size=0.25, goal_sample_rate=0.05)`.
- Inputs and outputs are compatible with the standard RRT planner.

Integration:
- The pipeline (`full_pipeline/scripts/main_connect.py`) uses `rrt_connect_plan` for path planning.

Algorithm Steps:
1. Sample a random point and extend the first tree toward it.
2. Attempt to connect the second tree to the new node (as far as possible without collision).
3. Alternate tree roles each iteration.
4. If the trees connect, reconstruct the path from start to goal.

For details, see `rrt_connect.py` and usage in `main_connect.py`.

Path Smoothing
--------------
After a path is generated by the RRT or RRT-Connect planner, it is often jagged due to random sampling. The `path_smoothing.py` module refines the path by attempting to shortcut segments between non-consecutive waypoints, provided the direct connection does not collide with any obstacles. This results in a smoother, more natural trajectory for the robot.

- The smoothing function (`smooth_path`) is automatically called after planning in the main pipeline scripts.
- Smoothing iteratively checks if two waypoints can be connected directly and, if so, replaces the intermediate points.
- This process preserves collision safety while reducing unnecessary turns and zig-zags.

Limitations
-----------
- This is a basic RRT; it does not smooth the path. Consider adding a post-processing step
  (e.g., shortcutting or spline smoothing) for smoother trajectories suitable for real robots.
- The planner is single-threaded and may block the main loop if `max_iter` is large; run infrequently
  (e.g., every 0.5s) or in a background thread for real-time systems.
